# v0.0.2 Vision Agent (Callable + Traceable)

PRD source: [PRD_philippo_v0.0.2.md](file:///Users/philipclaw/Downloads/TraeSolo/PilatesProject/NewCareers/PRD_philippo_v0.0.2.md)

## Goal

Validate, from first principles, that a Qwen multimodal model (`qwen-vl-*`) is:

- Successfully callable via DashScope API
- Traceable per request using `request_id` returned by DashScope
- Executed in the same `/api/generate?debug=1` request lifecycle used by v0.0.1
- Enforced by strict mode (`STRICT_LLM=1`) so failures are explicit (no silent skip)

## Non-goals (this step)

- Multi-image fusion logic
- OCR extraction / persistence / background removal
- Full context merge and listing quality evaluation changes

## Data Flow (v0.0.2 step 1)

1) Frontend uploads 1–5 images (required by PRD) + seller text
2) Backend converts at least one image to a `data:<mime>;base64,<...>` URL
3) Pipeline order (incremental):
   - Language Agent (text model)
   - Vision Agent (multimodal model)
   - Existing agents continue (product/keyword/seo/compliance/evaluation/formatter)
4) Response includes:
   - Existing listing result
   - `vision_context` (new field)
   - `_debug.calls[]` including `vision` call meta (endpoint/model/requestId)

## API Endpoints

Text generation (existing):

- `POST {DASHSCOPE_BASE_URL}/services/aigc/text-generation/generation`

Multimodal generation (DashScope API reference):

- `POST {DASHSCOPE_BASE_URL}/services/aigc/multimodal-generation/generation`

## Environment Variables

- `DASHSCOPE_API_KEY` (existing)
- `DASHSCOPE_BASE_URL` (existing, configurable for region; must not include quotes/backticks)
- `DASHSCOPE_TEXT_PATH` (existing)
- `QWEN_TEXT_MODEL` (existing)
- `DASHSCOPE_VL_PATH` (new, default `/services/aigc/multimodal-generation/generation`)
- `QWEN_VL_MODEL` (new, default `qwen-vl-max`)
- `QWEN_VL_FALLBACK_MODEL` (new, default `qwen-vl-plus`; used only when not strict)
- `STRICT_LLM` (existing)
- `DEBUG_LLM` (existing)

## Debug / Strict Rules

- `debug` is enabled when `?debug=1` OR `DEBUG_LLM=1` OR `STRICT_LLM=1` OR not production
- `STRICT_LLM=1`:
  - Vision Agent must succeed, otherwise the whole request fails with 500
  - No fallback model usage
- Non-strict:
  - May attempt `QWEN_VL_FALLBACK_MODEL` if the primary model fails
  - Still records failures and fallback attempts in `_debug.calls[]`

## Success Criteria (for step 1)

One `Generate` action produces:

- `_debug.calls[]` contains:
  - `agent="vision"` with `status="ok"` and a non-empty `requestId`
- `vision_context` exists in response and matches schema:
  - `category/material/visual_features/possible_customer`
