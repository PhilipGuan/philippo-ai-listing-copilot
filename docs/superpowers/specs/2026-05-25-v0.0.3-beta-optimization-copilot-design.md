# v0.0.3-beta Optimization Copilot Design

PRD source: [PRD_v0.0.3-beta.md](file:///Users/philipclaw/Downloads/TraeSolo/PilatesProject/NewCareers/PRD_v0.0.3-beta.md)

## Scope

Implement the “AI Listing Improvement Copilot” closed loop (FR-016~FR-021) on top of the existing v0.0.2/v0.0.3 work:

- FR-016 Gap Discovery Engine (local rule-based)
- FR-017 Image Quality Optimization Layer (local rule-based)
- FR-018 Missing Keyword Recommendation (local rule-based, weighted priority)
- FR-019 One Click Apply Suggestion (frontend-only, no new API)
- FR-020 Optimization Delta Compare (frontend-only, no new API)
- FR-021 Optimization Continuation Decision (local rule-based)

## Constraints / Decisions

- Approach: local rules/heuristics (no new LLM calls).
- Backward compatibility: add new fields, do not remove existing fields. Keep `seo_opportunity` while adding `optimization`, `delta`, `image_quality`.
- Apply behavior (FR-019): add keyword into ProductForm “Key Features” input (featuresText) to guide next generation.
- Frontend state model: ProductForm is controlled from `app/page.tsx` (Option 1).

## Backend Design

### New/Extended Types

Add to listing result (without breaking existing fields):

- `image_quality?: { clarity: number; focus: number; background: number; framing: number; hero_ctr_score: number; improvement: string[] }`
- `optimization?: { opportunities: Opportunity[]; keyword: KeywordOpportunity[]; image: ImageOpportunity[]; continue: boolean; reason: string }`
- `delta?: { overall: number; seo?: number; feature?: number; compliance?: number; readability?: number; image?: number }` (frontend-populated; backend may omit initially)

Opportunity model:

- `Opportunity = { type: "keyword" | "image"; priority: "high" | "medium" | "low"; reason: string; suggestion: string; meta?: Record<string, unknown> }`
- `KeywordOpportunity = { keyword: string; priority: "high" | "medium" | "low"; recommended_position: "Title" | "Bullet Point" | "Description" }`
- `ImageOpportunity = { suggestion: string; priority: "high" | "medium" | "low"; dimension?: "clarity" | "focus" | "background" | "framing" | "hero_ctr" }`

### New Local Agents

Agent execution occurs after listing generation is available (no extra LLM calls):

1) `imageQualityAgent` (FR-017)
- Inputs: uploaded image metadata (size, dimensions). Use rule-based estimation.
- Outputs: `image_quality` + `image` opportunities (background/clarity/etc.) + improvements list.

2) `keywordOpportunityAgent` (FR-018)
- Inputs: `ctx.keywords` (primary/secondary/long_tail) + listing text.
- Priority weighting: primary=3 → high; secondary=2 → medium; long_tail=1 → low.
- Output: keyword opportunities + recommended position.

3) `gapDiscoveryAgent` (FR-016)
- Inputs: listing + evaluation + keyword opportunities + image quality findings.
- Output: unified `optimization.opportunities[]` sorted by priority.

4) `optimizationDecisionAgent` (FR-021)
- Inputs: evaluation + opportunities.
- Output: `optimization.continue` boolean and `optimization.reason`.
- Rule: estimate expected gain; continue only if expected gain > 3.

### Pipeline Integration

Keep existing generation pipeline intact; append local agents after evaluation/formatter stages.

### Debug/Explainability

- Keep existing `_debug.calls[]` structure.
- For local optimization agents, add `status:"local"` debug records with summary `details` (counts, chosen reasons).

## Frontend Design

### Controlled ProductForm (Option 1)

Move ProductForm state ownership to `app/page.tsx`:

- `productInput` state stores all form fields including `featuresText`.
- `images` state remains in page to allow Apply + re-generation.
- ProductForm becomes controlled component:
  - `value`
  - `onChange(value)`
  - `images`
  - `onImagesChange(images)`
  - `onSubmit()`

### Apply Suggestion (FR-019)

When user clicks Apply on a keyword opportunity:

- Insert the keyword into `featuresText` (new line), de-duplicate (case-insensitive exact match).
- Scroll/focus features textarea (optional) and prompt user to click Generate again.
- No backend call at Apply time.

### Delta Compare (FR-020)

Maintain:

- `previousResult` (or at minimum previous evaluation snapshot)
- `currentResult`

On successful Generate:

- Shift `currentResult` → `previousResult`
- Set new `currentResult`
- Compute `delta` on frontend: overall and dimensions.

### Continue Decision (FR-021)

Use `result.optimization.continue` + `reason` to render:

- Continue=true: show “Optimize Again” CTA (re-Generate after Apply)
- Continue=false: show completion state.

### New UI Components

- `OptimizationPanel.tsx` (container)
- `ImprovementCard.tsx` (keyword/image opportunity card with Apply button for keyword)
- `DeltaCompare.tsx` (previous vs current)

## Acceptance Criteria

- Keyword opportunities show priority + recommended position.
- Apply inserts keyword into Key Features input without manual copy.
- Second Generate produces a different listing and updates delta.
- Continue decision is visible and prevents infinite loops.
